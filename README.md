# CodeQuant2: Enhanced Outlier Mitigation and Adaptive Clustering for Low-Precision LRMs

<p align="center" style="font-size: 24px;">
  Conference on Neural Information Processing Systems (NeurIPS), 2026
</p>

<p align="center">
  <a href="https://arxiv.org/abs/2611.09868"><img src="https://img.shields.io/badge/arXiv-2611.09868-b31b1b.svg" alt="arXiv:2611.09868"></a>
</p>

This repository provides the official implementation of **CodeQuant2**, a
clustering-based quantization framework for **large reasoning models (LRMs)**.
CodeQuant2 combines reasoning-aware calibration, fine-tuned rotation and scaling,
adaptive cluster allocation, and learnable clustering to preserve reasoning
performance under low-precision weight and activation quantization.

## ⭐ Highlights

- **Reasoning-aware calibration (RAC):** mix general text with early reasoning
  tokens generated by the full-precision model to capture decoding-time
  activation behavior.
- **Fine-tuned rotation and scaling:** smooth activation outliers before
  low-bit quantization.
- **Adaptive cluster allocation (ACA):** allocate 8, 16, or 32 centroids per
  target weight matrix instead of using one codebook size throughout the model.
- **Learnable clustering:** fine-tune centroid values and LoRA-parameterized
  assignments with local reconstruction losses.
- **A4W4 release configs:** examples for Qwen3-4B-Thinking, Qwen3-8B, and
  Phi-4-Reasoning, with vLLM and EvalScope downstream evaluation.
- **CUDA decoding kernel:** packed A4 activations and 4-bit weight indices
  with per-output-channel codebooks, shared-memory product lookup tables,
  and split-K reduction.

## 🔧 Requirements

Use a Python environment with an NVIDIA CUDA GPU and install the dependencies
listed in [`requirements.txt`](requirements.txt):

```shell
pip install -r requirements.txt
```

The requirements pin PyTorch, Transformers, vLLM, EvalScope, and the supporting
packages. Weights & Biases logging is optional and enabled with `--wandb` in
the rotation and clustering fine-tuning scripts.
Runs are logged to the `codequant2` project.

## 👨‍💻 Pipeline

The pipeline and its configuration are separate. The release provides the
following **A4W4** examples in [`config/`](config/):

| Model | Config |
|---|---|
| Qwen/Qwen3-4B-Thinking-2507 | [qwen3_4b_thinking_a4w4.yaml](config/qwen3_4b_thinking_a4w4.yaml) |
| Qwen/Qwen3-8B | [qwen3_8b_a4w4.yaml](config/qwen3_8b_a4w4.yaml) |
| microsoft/Phi-4-reasoning | [phi4_reasoning_a4w4.yaml](config/phi4_reasoning_a4w4.yaml) |

Copy the example for your model and set `path.rotation` and `path.clustering`
to writable output directories:

```shell
cp config/qwen3_4b_thinking_a4w4.yaml config/my_run.yaml
```

### 🎯 Run

The scripts are in [`script/`](script/). **Run every command from the repository
root.** Use the same experiment YAML for each stage.

**Step 1: Generate full-precision reasoning traces for RAC.**

```shell
python script/gen_vllm.py --config config/my_run.yaml
```

The release configs generate up to **256 new tokens** per GSM8K prompt. The
traces are mixed with WikiText-2 at a 1:9 ratio, and calibration sequences are
truncated and padded to **512 tokens**. The output is
`<path.rotation>/<model_type>_reasoning_gen.jsonl`, where `<model_type>` is the
model name without its organization, such as `Qwen3-4B-Thinking-2507`.

Pass `--model-dir /path/to/hf/model` to use a local model snapshot. Without
this flag, the script resolves the configured model from Hugging Face.

**Step 2: Fine-tune the rotation matrix and scaling vectors.**

```shell
python script/rotation_finetune.py --config config/my_run.yaml
```

Output: `<path.rotation>/<model_type>_r1_finetune.pt`.

**Step 3: Run adaptive cluster allocation.**

```shell
python script/adap_clus.py --config config/my_run.yaml
```

ACA considers the cluster counts `{8, 16, 32}` and processes target matrices
in groups of ten transformer layers. Output:
`<path.clustering>/<model_type>_cluster_assignment.yaml`.

**Step 4: Fine-tune clustered weights and assignments.**

```shell
python script/finetune_local.py --config config/my_run.yaml
```

This stage loads the rotation checkpoint and cluster allocation, fine-tunes
the centroids and assignments, and writes the reconstructed clustered weights
into a dense Hugging Face checkpoint at `<path.clustering>/final_model`.

**Step 5: Evaluate.**

For Qwen models:

```shell
python script/eval_thinking_vllm.py \
  --config config/my_run.yaml \
  --model-dir /path/to/clustering/final_model \
  --clean-tmp-dir /path/to/tmp/vllm_clean \
  --cache-root /path/to/cache
```

For Phi-4-Reasoning, copy its config and edit the output paths in the same way.
Use that YAML and also provide the original Hugging Face tokenizer snapshot:

```shell
python script/eval_thinking_vllm_phi.py \
  --config config/my_phi_run.yaml \
  --model-dir /path/to/clustering/final_model \
  --clean-tmp-dir /path/to/tmp/vllm_clean \
  --cache-root /path/to/cache \
  --tokenizer-path /path/to/original/phi4/hf/snapshot
```

Replace the example paths with your output and cache directories. The scripts
first run a local perplexity check on WikiText-2 test and C4 validation, then
start vLLM with the `act_quant` activation fake-quantization plugin and run
EvalScope. Downstream benchmarks include MATH500, GSM8K, AIME25, AIME26,
HumanEval, LiveCodeBench, ARC, PIQA, and WinoGrande.

Useful evaluation flags:

- `--config`: read the activation bit-width from the experiment YAML.
- `--skip-ppl`: skip the local perplexity check.
- `--no-quantization`: disable the vLLM activation-quantization plugin.
- `--server-only`: start the vLLM server without running evaluations.
- `--cache-root`: select the root directory for HF, ModelScope, and vLLM caches.
  The same root can be set with the `CODEQUANT2_CACHE_ROOT` environment variable.

### 🔎 Config

Use the model-specific YAML as a starting point. The main parameters are:

| Section | Parameters | Description |
|---|---|---|
| Root | `model_name`, `device`, `tie` | Model identifier, training device, and whether to untie the language-model head from the embeddings before rotation. |
| `path` | `rotation`, `clustering` | Directories for calibration traces and rotation checkpoints, and for cluster allocation and the final model. |
| `rotation` | `max_sample`, `batch_size`, `max_length`, `epochs` | Calibration sample count, batch size, padded sequence length, and epochs per rotation/scaling stage. |
| `rotation` | `fine_tune_lr` | Adam learning rate for rotation and scaling; the release uses `0.001`. |
| `rotation` | `wiki_dataset`, `wiki_ratio` | General-text calibration source and its fraction in the mixed samples; the release uses `0.9`. |
| `rotation` | `pretrained_rotation_path` | Optional rotation checkpoint; when set, skip rotation training and train only scaling vectors. |
| `evaluation.generation` | `max_tokens` | Maximum newly generated RAC tokens; the release uses `256`. |
| `evaluation.vllm` | `tensor_parallel`, `gpu_mem_util` | Optional vLLM settings for RAC trace generation. Generation defaults to two-way tensor parallelism; set `tensor_parallel: 1` for one GPU. |
| `adap_clus_para` | `batch_size`, `max_length` | ACA calibration batch size and padded sequence length. |
| `bits` | `activation`, `cluster_num` | Activation bit-width and default centroid count per output row; the release uses `4` and `16`. |
| `bits` | `assignment_cluster_number` | Load the per-matrix cluster allocation from step 3. |
| `training_para` | `size`, `batch_size`, `max_length`, `epochs` | Local fine-tuning sample count, batch size, padded sequence length, and epochs; defaults are `512`, `16`, `512`, and `4`. |
| `training_para` | `wiki_dataset`, `wiki_ratio` | General-text source and mixture ratio for local fine-tuning. |
| `training_para` | `target_layers` | Projection layers to cluster; keep the model-specific names in the provided YAML. |
| `training_para` | `use_assignment_lora`, `a_lora_r` | Enable assignment updates and select their LoRA rank. |
| `training_para` | `start_temp`, `end_temp`, `hard_ratio` | Soft-assignment temperature schedule; the release uses `0.1`, `0.001`, and `0.98`, followed by hard assignments. |
| `training_para` | `lr_c` | Centroid SGD learning rate; the release uses `0.0001`. Assignment SGD uses `0.00001`. |
| `training_para` | `loss1_weight` | Weight of quantized-input reconstruction loss relative to clean-input reconstruction loss. |

The `evaluation.generation` and `evaluation.vllm` sections configure **RAC
trace generation**. Downstream evaluation tasks and decoding settings are
defined in [`script/eval_thinking_vllm.py`](script/eval_thinking_vllm.py) and
[`script/eval_thinking_vllm_phi.py`](script/eval_thinking_vllm_phi.py).
Use decimal notation for YAML learning rates, for example `0.001`.

## ⚡ CUDA Decoding Kernel

[`kernel/lut_kernel.py`](kernel/lut_kernel.py) provides a standalone CUDA
kernel for decoding. Each output channel has a 16-entry FP16 codebook.
The kernel builds shared-memory tables of products of centroids and activation indices,
replaces multiplications in the K loop with lookups, and combines split-K
partial sums into FP16 outputs.

The supported input shape is `[M, K]` with **1–16 decoding rows** and `K`
divisible by eight. Activations and weight indices are packed eight 4-bit
values per int32, with the first value in the lowest four bits. This entrypoint
uses **16 centroids per output channel**; ACA allocations of 8 or 32 centroids
require a separate representation or kernel.

All buffers must be contiguous CUDA tensors on the current device:

| Tensor | Shape | Dtype |
|---|---|---|
| `packed_activations` | `[M, K/8]` | `int32` |
| `packed_weights` | `[K/8, N]` | `int32` |
| `centroids` | `[N, 16]` | `float16` |
| `min_max` | `[M, 2]`, per-row minimum and maximum | `float32` |
| `weight_sums` | `[N]` | `float32` |
| `partials` | `[split_k, M, N]` | `float32` |
| `output` | `[M, N]` | `float16` |

Given prepacked inputs and reusable workspace/output buffers:

```python
from kernel.lut_kernel import row_lut, precompute_csum

# Compute once when loading the packed weights and codebooks.
weight_sums = precompute_csum(packed_weights, centroids, K)

# Run once per decoding step. split_k > 0; threads_per_column is 4, 8, or 16.
row_lut(
    packed_activations, packed_weights, centroids, min_max,
    weight_sums, partials, output,
    M, N, K // 8, split_k, threads_per_column,
)
```

Activation quantization and packing are performed by the caller. Importing
the module compiles the extension for the current GPU using PyTorch's JIT
extension loader; a CUDA-enabled PyTorch environment, CUDA toolkit with
`nvcc`, a compatible C++ compiler, and Ninja are required. The kernel is a
direct-call entrypoint for decoding integration; the evaluation commands above
use the vLLM activation fake-quantization plugin.
